# The Clawpack source tree each *released* documentation version is built
# against: <doc version> <clawpack/clawpack commit> [# tag].
#
# WHY THIS FILE EXISTS
#
# sphinx-multiversion builds every version with dev's conf.py, so without this
# every version directory would get its API pages from the one tree pinned in
# clawpack-ref.txt -- i.e. current master.  A release's .rst names modules as
# they were at that release; where master has since renamed them (surge.storm
# -> met.storm) autodoc fails to import and the page comes out silently empty,
# and everywhere else the release pages document code that release never
# shipped.
#
# Each row pins the super-repo commit of the release's newest patch tag.  The
# subrepo commits come from that commit's submodule pointers, exactly as the
# release shipped them; tools/fetch_clawpack_src.py --releases materialises
# one tree per row, and ext/clawpack_source.py selects the tree for the
# version being built.  `dev` is not listed: it documents clawpack-ref.txt.
#
# check_versions.py fails if a buildable release version has no row, or a row
# names a version that is not built.  When cutting a release, add its row here
# (and bump the row when a patch release follows).
